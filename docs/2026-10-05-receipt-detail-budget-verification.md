# MPay 防誤記、記錄詳情與預算鎖定驗收

日期：2026-10-05。實機：Samsung SM-S9210，Android 16 / API 36。

## 修改內容

- 底部五個欄位均分；中央新增圓形按鈕保留 44dp 視覺直徑。
- MPay 歷史帳單、轉帳詳情及錢包列表永不建立新帳目。輸入、待確認、失敗及退款頁也不記錄。其他支付應用增加歷史收付款詳情、帳單和聊天頁的排除。
- 自動記錄以「來源包名 + 交易編號」永久核對，同額不同編號可分別入帳；通知與讀屏使用同一個儲存庫原子判斷。永久刪除帳目不會清除其防重複身份。舊版已有單號的記錄在清理前補入身份登記。
- 記錄增加來源、來源管道、交易編號及原交易時間；編輯內容保留這些欄位。可識別的舊版讀屏 ID 補回來源及編號，無法識別的舊資料標示來源未提供。
- 點記錄顯示置中唯讀詳情，含分類、備註、時間、來源及編號。明細及搜尋的編輯入口均改為左滑後的編輯按鈕；浮球與通知點擊同樣開詳情。
- 數字鍵盤抽取為 `AmountKeypad` 共用 Compose 函式，0 佔三個數字欄寬，保存佔右側第四欄。
- 總預算與分類預算可分別鎖定，自所選當月或未來月份起每月沿用；鎖定期間不能修改或清除。解鎖保留已生效月份的金額，未來恢復各月原本設定。分類改名同步移轉鎖定模板。

## 自動記帳的準確性界線

本段限制已由後續通知層級修正取代：MPay 的成功頁和通知不提供交易編號，編號不能作為入帳的必要條件。MPay 改由通知建立帳目，無障礙補充可精確核對的資料；新成功頁不再要求單號。仍不按「同額」或「時間接近」猜測帳單。歷史詳情只可為具有共同來源、金額和原交易時間的唯一既有候選補充編號，絕不建立帳目；不符合或有歧義時略過。詳見 `2026-10-05-mpay-notification-verification.md`。

本次沒有進行實際付款，新的真實付款結果與推播格式仍須在使用者正常付款時核對。不能將 parser 的正向單元測試當作已完成真實付款驗證。

## MPay 本地帳單資料可否直接讀取

正常 Android App 權限不能直接讀取另一 App 的私有資料庫，無障礙權限也不會解除應用隔離。安裝於此手機的 MPay 沒有 DEBUGGABLE 旗標；已檢查的 provider 列表未找到可供本程式讀取的帳單介面。本次未找到可使用的個人帳單公開 API，因此沒有加入直接讀取 MPay 私有資料庫的實作。

依據：[Android Application Sandbox](https://source.android.com/docs/security/app-sandbox)。MPay 官方提供帳單查閱說明：[澳門錢包常見問題](https://macaupass.com/MPayfaqs)。未找到公開 API 是本次調查結果，並不表示 MPay 內部不存在帳單服務。
