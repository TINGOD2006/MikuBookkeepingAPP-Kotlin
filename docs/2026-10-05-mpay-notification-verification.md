# MPay 通知記錄及三層設定驗證

## 修正原因與行為

先前把 MPay 的通知及成功頁交易編號設為必要，導致真實付款漏記。使用者確認編號只在歷史帳單頁顯示，本次移除該限制。

- 手動：不讀取交易通知或畫面。
- 通知：所選支付 App 的交易通知入帳，不走訪支付畫面。
- 通知＋無障礙：保留通知入帳，另外讀取畫面。MPay 統一由通知新增，畫面只精確補充資料，避免無編號的通知與畫面各記一次。
- 通知允許既有「消費 MOP 金額」行文，無須額外成功字樣或單號；廣告、失敗、退款、請求及待付款內容不記。
- 金額相同本身不去重。通知用 Android key 與來源時間辨識，同通知更新內容保持身份；編號存在時仍採永久帳單身份。
- 首次升級登記已在通知欄的舊通知身份，不回補安裝前帳目。舊通知重送命中後補登記新身份，避免隨後內容更新重記。
- 舊版已開啟主開關遷移到通知層；新安裝仍預設手動，最高層需使用者自行選擇。

## 邊界

通知讀取權限與 MPay 允許發送交易通知都需啟用。系統無障礙授權保留，並不會自行提高選用的記錄層級；通知層仍可用該服務顯示系統浮球。

若通知和詳情沒有共同明示交易時間，或候選不唯一，不能自動補上編號；安全保留原來無編號的帳目。通知 key 與來源時間是可用的事件身份，無單號的資料不能宣稱具有帳單伺服器提供的永久唯一性。
